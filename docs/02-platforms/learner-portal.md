# Learner Portal (LMS)

The shared post-purchase learning platform for paid students of every brand. See
`docs/01-backend/learner-portal-engines.md` for the full enrollment/vault/referral engine
documentation — that whole document is built from this platform.

## Identity

- Framework: Vite + React, bun.
- Supabase: estate project, schema `lms`, with a hand-written browser client pinned to that
  schema (`src/integrations/lms/client.ts`). The Lovable-autogenerated client points at a dead
  leftover project and only one test imports it — a trap worth knowing before trusting
  `.env`/`config.toml` alone to answer "which project does this repo use."
- Scale: ~3,445 commits, ~80 migrations, ~82 edge functions, ~110 tables — the most mature
  codebase in the estate.

## Roles and pages

Three portals in one app: Student (dashboard, programs, upcoming programs, events,
announcements, community, vault, help, settings), Mentor (dashboard, programs, feedback,
community, announcements, profile), Admin (~24 pages: enrollment, students, sessions,
attendance, calendar, groups, recordings, resources, certificates, feedback, tickets,
WhatsApp, vault, team, emails, settings).

## What it owns

- The enrollment engine (`_shared/enrollment-engine.ts` + `enrollment-rules.ts`): a single
  state machine every enrollment path calls, with pinned-row protection and stale-event
  rejection.
- The throttled login rollout (`login-rollout`), onboarding pre-existing students in bounded
  batches rather than all at once.
- The Vault: a double-entry credit ledger with trigger-driven earning, locked spending, and
  daily integrity reconciliation.
- Two independent referral rewards (a flat invitation reward and a percentage programme
  reward), each with its own anti-abuse rules.
- Session/attendance, community (channels, messages, AI-reviewed moderation), certificates,
  support tickets, grade promotion, masterclass cross-platform registration matching.

## Session policy

Sessions persist indefinitely across devices; sign-out is always local-scope except an
explicit admin "sign out everywhere." Storage choice (`localStorage` vs `sessionStorage`)
implements "keep me signed in," not a server-side flag. The app revalidates on
`visibilitychange`/`focus`/`online`/cross-tab storage events plus a 5-minute interval, and
retries `getSession()` once after 800ms before denying a route, to survive token-rotation
races.

## The namespace migration

A careful rename of 40 edge-function endpoints onto a single `lms_<name>` prefix on a shared
project where other platforms also deploy functions: deploy the new names first, rewire only
the existing cron jobs, publish the client, and retain the old names as a compatibility layer
until caller verification is complete. Explicitly, no retry/fallback logic was added anywhere
in the cutover, because an ambiguous failure must never duplicate a password, an enrollment
action, an email, a WhatsApp send or a wallet write.

## A model audit artefact

A read-only reconciliation audit (`docs/student-reconciliation-20261116.md` in the source
repo) is worth reading as a template for any future one: it states exact verified counts, lists
every exception that needs a human with the specific conflicting facts (never guessed or
merged), and ends with an honest statement of what the audit did **not** fix.
